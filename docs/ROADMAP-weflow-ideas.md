# WeFlow 功能对照与落地计划

对照开源项目 [WeFlow](https://github.com/hicccc77/WeFlow)（本地微信聊天查看 / 导出 / 年度报告）。  
本仓库定位是 **Windows 备份后分析导出**（非实时挂钩），因此只吸收与架构匹配的 idea；依赖实时注入 / 防撤回 / 桌面通知的能力标为「暂不纳入」。

## 我们已有（大致对齐）

| WeFlow | WeChat Export |
|--------|----------------|
| 聊天记录查看 | 聊天查看器（备份后） |
| 多格式导出 | TXT / HTML / Excel / CSV / Markdown / JSON / PGSQL / ChatLab 等 |
| 年度报告 | Wrapped 年度报告 |
| 双人报告 | `/duo` 好友选择 + 双向互动卡片 |
| 群聊画像 | `/group` 成员排行 / 时段 / 媒体 |
| 统计分析 / 词云 | 综合报告、词云、会话报告包 |
| 联系人 | 通讯录浏览与导出 |
| 语音相关 | 语音播放、转写、按人导出 |
| HTTP 能力 | 本地 Flask API / ChatLab Pull / `/api-docs` |
| 增量 | 增量备份（库指纹 + 媒体硬链接） |
| 朋友圈（离线） | `/sns` + `sns.db` 解密 / ISAAC 媒体 |
| 实况图 | 聊天 XML 识别 + 朋友圈 Live 对 |

## 差距清单（按优先级）

### P0 — 体验价值高、可基于现有备份数据做

- [x] **双人报告**：选定一个好友，生成双方互动专属报告（时段、回复速度、关键词、表情等；可复用 Wrapped 卡片）→ `/duo` + 会话 Wrapped 双向卡片
- [x] **群聊画像**：群成员发言排行、活跃时段、媒体占比（独立分析页）→ `/group` + 会话 Wrapped 群卡片
- [x] **私聊分析页**：1:1 类型占比 / 发送比例 / 时段热力 → 复用 `/duo`；聊天查看器顶栏「分析」一键进入

### P1 — 导出与开发者能力补齐

- [x] **导出格式补齐**：Markdown、纯 JSON（消息数组）、PostgreSQL SQL dump → 导出页可选
- [x] **公开 HTTP API 文档**：`docs/HTTP-API.md` + 应用内 `/api-docs`（本地无鉴权说明）
- [x] **联系人增强**：通讯录「公众号」页签；「历史」页签列出有聊天但通讯录缺失的会话（尽力而为）

### P2 — 媒体与内容深度

- [x] **实况 / Live Photo**：聊天图片 XML 识别 `livePhoto`/`islive`；气泡标注「实况」并尝试挂载本地视频轨；朋友圈媒体同样解析实况对
- [x] **朋友圈（离线）**：备份解密 `sns/sns.db` → `/sns` 只读时间线 + HTML/JSON 导出；媒体优先本地缓存，否则 CDN + ISAAC-64（不做删除拦截）

### P3 — 平台与产品化（长期）

- [ ] **跨平台安装包**：macOS / Linux（WeChat 4.x 数据路径与密钥提取差异大，工作量大）
- [ ] **桌面壳**：Electron/Tauri 包装现有 Web UI（非必须）

## 明确不做 / 暂缓（与当前架构冲突）

| WeFlow 能力 | 原因 |
|-------------|------|
| 实时查看（不备份） | 依赖原生解密组件 / 进程挂钩 |
| 消息防撤回 | 需实时挂钩 |
| 新消息桌面弹窗 / 黑白名单 | 需实时监听 |
| 修改本地消息 | 写回微信库风险高，且需挂钩 |
| 拦截朋友圈删除/隐藏 | 实时挂钩 |

> Tip：WeFlow 自身也依赖「第三方可插拔原生解密组件」，见其 `docs/third-party-components.md`。我们继续走 **备份解密 → 分析导出** 路线，避免与其抢同一套实时能力。
