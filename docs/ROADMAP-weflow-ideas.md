# WeFlow 功能对照与落地计划

对照开源项目 [WeFlow](https://github.com/hicccc77/WeFlow)（本地微信聊天查看 / 导出 / 年度报告）。  
本仓库定位是 **Windows 备份后分析导出**（非实时挂钩），因此只吸收与架构匹配的 idea；依赖实时注入 / 防撤回 / 桌面通知的能力标为「暂不纳入」。

## 我们已有（大致对齐）

| WeFlow | WeChat Export |
|--------|----------------|
| 聊天记录查看 | 聊天查看器（备份后） |
| 多格式导出 | TXT / HTML / Excel / CSV / ChatLab 等 |
| 年度报告 | Wrapped 年度报告 |
| 统计分析 / 词云 | 综合报告、词云、会话报告包 |
| 联系人 | 通讯录浏览与导出 |
| 语音相关 | 语音播放、转写、按人导出 |
| HTTP 能力 | 本地 Flask API / ChatLab Pull |
| 增量 | 增量备份（库指纹 + 媒体硬链接） |

## 差距清单（按优先级）

### P0 — 体验价值高、可基于现有备份数据做

- [ ] **双人报告**：选定一个好友，生成双方互动专属报告（时段、回复速度、关键词、表情等；可复用 Wrapped 卡片）
- [ ] **群聊画像**：群成员发言排行、活跃时段、媒体占比、入群以来趋势（独立分析页，不只是聊天列表）
- [ ] **私聊分析页**：1:1 会话的类型占比、发送比例、时段热力（从报告入口一键进入）

### P1 — 导出与开发者能力补齐

- [ ] **导出格式补齐**：Markdown、纯 JSON（消息数组）、可选 PGSQL `COPY`/SQL dump（WeFlow 宣传的格式）
- [ ] **公开 HTTP API 文档**：整理现有 `/api/*` 为开发者文档（OpenAPI / Markdown），设置页可开关与查看端口说明
- [ ] **联系人增强**：公众号列表导出；「可能的历史好友 / 已删除联系人」尽力从 contact 库残留找回（能做多少做多少）

### P2 — 媒体与内容深度

- [ ] **实况 / Live Photo**：聊天中的实况图识别与导出（需调研微信 4.x 存储形态）
- [ ] **朋友圈（离线）**：若能从本地库解密朋友圈图文视频，做只读浏览 + 导出（不做删除拦截）

### P3 — 平台与产品化（长期）

- [ ] **跨平台安装包**：macOS / Linux（WeChat 4.x 数据路径与密钥提取差异大，工作量大）
- [ ] **桌面壳**：Electron/Tauri 包装现有 Web UI（非必须）

## 明确不做 / 暂缓（与当前架构冲突）

| WeFlow 能力 | 原因 |
|-------------|------|
| 实时查看（不备份） | 依赖原生解密组件 / 进程挂钩 |
| 消息防撤回 | 需实时挂钩 |
| 新消息桌面弹窗 / 黑白名单 | 需实时监听 |
| 修改本地消息 | 写回微信库风险高，且需挂钩 |
| 拦截朋友圈删除/隐藏 | 实时挂钩 |

> Tip：WeFlow 自身也依赖「第三方可插拔原生解密组件」，见其 `docs/third-party-components.md`。我们继续走 **备份解密 → 分析导出** 路线，避免与其抢同一套实时能力。

## 建议实施顺序

1. 双人报告  
2. 群聊画像  
3. 私聊分析页  
4. Markdown / JSON 导出  
5. HTTP API 文档页  
6. 联系人增强  
7. 实况 / 朋友圈调研后再排期  

完成一项勾掉一项；每项尽量单独提交，便于回滚与发版说明。
